GitHub install

Install metro. Then look up a customer - not Metronome screens.

Metro is for engineers who need billing answers without learning Metronome's UI or config maze. Install the standalone CLI from the GitHub repo (no full ops checkout). Prove it locally with no API key. Live reads and writes stay gated: you confirm before anything touches a customer.

First Safe Preview

Minimum success path Install from GitHub, print the quickstart, then run its local checks.
  1. Install (clone once, then script) git clone --depth 1 https://github.com/metrocli/metro.git ~/.metro/src bash ~/.metro/src/scripts/install-global.sh metro --help
  2. Guide metro setup quickstart --shell | zsh
  3. Discover metro schema --json

  5. Bind metro setup resolve --file "$METRO_QUICKSTART_DIR/profiles.json" --profile my-sandbox --expect-tenant sandbox --key-fingerprint fp_sandbox_setup_resolve_reviewed --json

Prerequisites

Use Node.js and npm plus GitHub access to metrocli/metro. Users do not need any parent billing-operations monorepo checkout. Do not load .env files; the quickstart prints only secret-free local evidence.

Expected preview shape

{

  "workflow": "package.create",
  "shape": "pro-annual",
  "tenant": "sandbox",
  "payloadHash": "sha256:...",

The preview is sandbox-labeled, hash-bound, and local-only. A green preview is not production approval and does not authorize live reads, live writes, Stripe delivery, or package apply.

Automation integration contract

Use metro schema --json for command discovery and parse only documented JSON schemas from stdout. Validation failures exit 1. Live-read, live-write, or unsupported-operation refusals exit 2 and may emit metro.refusal.v1 or endpoint-specific refusal JSON on stderr.

Treat every --json payload as local evidence unless the current turn explicitly authorizes the exact live operation. Do not infer authorization from profile files, environment variable names, key presence, fixture paths, preview hashes, or passing apply-gate validation.

Next safe step

Use metro docs command-reference --html or metro api readiness --summary --json to inspect broader local coverage, then metro api readiness --json for endpoint-level detail. Before any future live operation, require exact current-turn authorization plus the preflight, audit, sandbox proof, read-back, rollback, and approval gates documented here.

4. Generate a profile skeleton

metro setup template --json
metro setup resolve --file profiles.json --profile my-sandbox --expect-tenant sandbox --key-fingerprint fp_sandbox_setup_resolve_reviewed --json

Produces tenant-scoped profile JSON that names environment variables and resolves one secret-free tenant binding. It does not read .env files, print key values, or authorize live API access.

5. Bind expert API gate evidence

metro api preflight template --preview api-preview.json --profile-resolution profile-resolution.json --approval-id approval-local-contracts-create-001 --json
metro api preflight validate --file api-preflight.json --json
metro api apply-gate template --preview api-preview.json --preflight api-preflight.json --sandbox-proof api-sandbox-proof.json --profile-resolution profile-resolution.json --approval-id approval-local-contracts-create-001 --owner billing-ops --key-env METRONOME_SANDBOX_KEY --key-fingerprint fp_sandbox_contracts_create_reviewed --audit-log audit-logs/api-contracts-create-sandbox.jsonl --json

Binds the reviewed API preview to tenant-profile resolution, sandbox proof, approval, key fingerprint, audit destination, read-back, rollback, and idempotency evidence. Sandbox contracts.create is the only live apply path today; production writes and workflow applies remain blocked.

6. Validate local input

metro validate --shape pro-annual --file pro-annual.json --json

Runs executable local rules against JSON or YAML fixture input before any preview plan is rendered.

7. Render a sandbox preview

metro package preview --shape pro-annual --file pro-annual.json --sandbox --json

Emits a local payload plan, side-effect summary, verification plan, and canonical hash without loading Metronome clients.

Guarded Live Operations

8. Guarded live operations (optional)

export METRONOME_SANDBOX_KEY='your-sandbox-key'
metro api read contracts.get.v2 --file request.json --sandbox \
  --read-gate read-gate.json \
  --confirm-live-read I_UNDERSTAND_THIS_WILL_READ_LIVE_METRONOME --json
metro api apply contracts.create --file request.json --sandbox \
  --apply-gate api-apply-gate.json \
  --approval-record api-approval-record.json \
  --confirm-live-apply I_UNDERSTAND_THIS_WILL_WRITE_LIVE_METRONOME_SANDBOX --json

See TEAM-QUICKSTART.md in the installed package for the full team onboarding path. Live reads are limited to contracts.get.v2, customers.get, and invoices.listForCustomer per Metronome API docs. Without keys and gates, these commands refuse on stderr with exit code 2.

9. Keep workflow apply blocked

metro package apply --shape pro-annual --file package.json --prod

Workflow apply commands remain unsupported until reviewed preview hashes, preflight evidence, sandbox proof, audit logs, read-back checks, rollback, and approval gates exist.

Setup Troubleshooting

ENOTDIR or metro: command not found after global install

Root cause: npm install -g git+https://github.com/metrocli/metro.git is broken on current npm for this package. It leaves $(npm root -g)/@metrocli/metro pointing at ~/.npm/_cacache/tmp/git-clone… with no bin/metro.js.

How it shows up:

  • install says added 1 package, then zsh: command not found: metro
  • or a later install fails with ENOTDIR: not a directory, rename '.../@metrocli/metro'

Confirm: 

ls -la "$(npm root -g)/@metrocli/metro"
# bad:  ... -> .../npm/_cacache/tmp/git-clone...   (no bin/metro.js)
# good: ... -> .../.metro/src   (or your checkout) with bin/metro.js

Fix: stop using npm install -g git+. Use clone + npm link (or bash ~/.metro/src/scripts/install-global.sh): 

git clone --depth 1 https://github.com/metrocli/metro.git ~/.metro/src
bash ~/.metro/src/scripts/install-global.sh
metro --help
metro setup quickstart --shell | zsh

Maintainers editing this checkout: npm link from the repo root. Also run npm test and npm run pack:verify before changing package metadata or setup instructions.

Profile doctor reports missing variables

Add the named variables to the shell environment for an authorized run. Do not paste raw key values into profile files, fixtures, docs, screenshots, or changelog notes.

A command asks for live inspect or apply

Use local --plan, preview, or validate forms unless the current user turn explicitly authorizes the exact live operation. The current CLI intentionally refuses live reads and writes.
