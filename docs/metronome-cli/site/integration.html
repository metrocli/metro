Integration

Integrate metro by contracts, not by scraped copy.

Use the CLI as a local evidence generator for automation, CI, and agent workflows. Stable JSON contracts, exit codes, source-linked command references, and explicit safety refusals are the integration boundary. Guarded live read and sandbox write paths exist for a small allowlist; everything else refuses until current-turn authorization and gate evidence are satisfied.

Treat these outputs as the integration source for command IDs, modes, required flags, schema versions, supported status, API access, permission scopes, and owner approval policies. Do not scrape prose from the home page when the CLI can emit the same contract directly.

Normalize input before evidence work

metro docs explain --list --json
metro docs explain --list --html
metro docs explain first-safe-preview --json
metro docs explain input.normalize --json
metro docs explain output.anatomy --json
metro input normalize --shape pro-annual --file pro-annual.yaml --json
metro input normalize --api contracts.create --file contracts-create.yaml --json

Inspect the local topics first, then use metro.input.normalize.v1 output as the stable JSON round-trip boundary for shape inputs and reviewed expert API requests. Use output.anatomy to parse schema versions, source links, hashes, refusal output, and next safe steps before a downstream agent treats any JSON as evidence.

Handle exit codes explicitly

0
Local command completed and emitted the requested contract or evidence.
1
Input, validation, fixture, or file-shape failure.
2
Safety refusal for unsupported live reads, live writes, or apply behavior.

Safety refusals may emit metro.refusal.v1 or endpoint-specific refusal JSON on stderr. A refusal is a useful integration result, not a reason to bypass the CLI.

CI Checks

Local-only Use checks that need no API keys and no tenant access.
  1. Install npm run test:install
  2. Unit npm run test:unit
  3. Golden npm run test:golden
  4. Site node docs/metronome-cli/site/verify-site.js

Add npm run check:syntax and npm run secrets:scan for repository-level checks after reviewing the root package scripts. These checks are local-only in this workspace, but they still protect a production operations repo.

Use the compact summary for quick gap counts, the full report when a family or endpoint needs fixture-level review, and the release commands to retain package/install evidence, validate the reviewed retention policy, plan manual artifact capture, and validate an operator-owned evidence bundle. These commands are local checks and keep live execution, npm registry access, and token handling disabled.

Safety Boundaries

Never infer authorization

Profile files, environment variable names, key presence, fixture paths, preview hashes, apply-gate validation, and passing CI are not authorization for live Metronome, Stripe, CRM, analytics, chat, email, or customer-impacting work.

Keep live verbs out of automation

The current CLI exposes local validation, previews, plans, mocked read pipelines, audit evidence, generated references, and proof checks. It does not expose live expert API read or apply commands. Do not wire automation to direct API clients as a shortcut around that boundary.

Use source-linked next steps

Start broad with metro api readiness --summary --json. Move to metro api readiness --json only when the summary shows a gap or a reviewer needs endpoint-level evidence. Update the changelog when docs, fixtures, generated pages, or command contracts change.
