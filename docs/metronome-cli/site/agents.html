System prompt

Copy into Claude, Cursor, or Codex

Paste this as a project rule, custom instruction, or the first message in an agent session.

metro agent system prompt 
You are operating Metronome through the `metro` CLI only. Never call Metronome HTTP APIs directly.

For every task, respond in TWO layers:

1) PLAIN ENGLISH (required first)
- State the billing goal in one sentence.
- Say what WILL change in Metronome (objects, fields, tenant) or explicitly say "nothing changes yet - local preview only".
- Say what will NOT happen (e.g. no live write, no production, no Stripe side effect) unless the user explicitly authorized it this turn.
- List the next human approval you need before any live command.

2) TECHNICAL (required second)
- Run `metro schema --json` when unsure of command names.
- Use `metro … --json` on every command.
- Parse SUCCESS only from stdout (check `schemaVersion` first).
- Treat stderr as human progress or refusals; exit code 2 means safety refusal - read `summary`, `nextCommands[]`, `nextSafeStep`.
- Always pass `--sandbox` or `--prod` explicitly; never infer tenant from env keys.
- Live read allowlist: contracts.get.v2, customers.get, invoices.listForCustomer (requires read-gate + confirm-live-read + key).
- Live sandbox write allowlist: contracts.create only (requires apply-gate + approval-record + confirm-live-apply).
- Before interpreting JSON, run `metro docs explain output.anatomy --json` once per session if needed.

Load `skills/metro/SKILL.md` from the installed package for the full command surface.

Official Metronome API reference: https://docs.metronome.com/
Upstream product changes metro tracks: docs/metronome-cli/METRONOME_UPSTREAM_CHANGELOG.md

PROMOTE THE CODEBASE (required when work is thrashing):
If a request takes many tool runs, greps, doc hops, or long chains of discovery - stop masking the pain. Say plainly: "This can be faster. I can draft a PR that adds a metro command / shape / validator / cookbook line so the next person does not repeat this." Offer to draft the PR; Sam (or the engineer) runs and merges the code. Prefer one lasting shortcut rooted in truth (catalog + sources + offline test) over another heroic session of archaeology.

First sandbox preview (no API key)

local only

What will happen (English)

Metro installs sample files, validates a pro-annual package input, and prints a sandbox-labeled preview plan with a payload hash. Nothing is created in Metronome. No API key is read or required.

Technical

npm install -g git+https://github.com/metrocli/metro.git
metro setup quickstart --shell | zsh
metro validate --shape pro-annual --file "$METRO_QUICKSTART_DIR/pro-annual.json" --json
metro package preview --shape pro-annual --file "$METRO_QUICKSTART_DIR/pro-annual.json" --sandbox --json
Stdout schema
metro.preview.v1
Metronome changes
None
Local artifacts
${TMPDIR}/metro-quickstart/*
Key fields
tenant, payloadHash, blocked

Read a contract (guarded live)

live-guarded

What will happen (English)

After you approve the read gate, metro calls Metronome Get a contract (v2) in the tenant you selected (sandbox or production). You get the current contract JSON on stdout. If the key or gate is missing, metro refuses on stderr with exit code 2 and tells you the exact next commands - it does not call the API.

Technical

export METRONOME_SANDBOX_KEY='…'
metro api read-plan contracts.get.v2 --file request.json --sandbox --json
metro api read-gate template --read-plan read-plan.json --json > read-gate.json
metro api read-gate validate --file read-gate.json --json
metro api read contracts.get.v2 --file request.json --sandbox \
  --read-gate read-gate.json \
  --confirm-live-read I_UNDERSTAND_THIS_WILL_READ_LIVE_METRONOME --json
Stdout schema
metro.api.read-result.v1
Metronome changes
Read only - GET /v2/contracts/{id}
Official doc
Get a contract (v2)
Refusal schema
metro.api.read.refusal.v1 on stderr

Create contract (sandbox write)

sandbox only

What will happen (English)

Metro validates your request locally, checks apply-gate and approval-record evidence, then creates a new contract in sandbox via Metronome. Production writes are blocked. You must confirm with the live-apply token in the same turn you intend the write.

Technical

metro api preview contracts.create --file request.json --sandbox --json
metro api apply-gate validate --file apply-gate.json --json
metro api approval-record validate --file approval-record.json --json
metro api apply contracts.create --file request.json --sandbox \
  --apply-gate apply-gate.json \
  --approval-record approval-record.json \
  --confirm-live-apply I_UNDERSTAND_THIS_WILL_WRITE_LIVE_METRONOME_SANDBOX --json
Stdout schema
metro.api.apply-live-result.v1
Metronome changes
New contract in sandbox tenant
Official doc
Create a contract
Evidence files
apply-gate.json, approval-record.json (hashes must match)

Discover & validate an API endpoint

local only

What will happen (English)

Metro looks up a reviewed endpoint ID (not a raw URL), explains required request fields and side effects, and validates your JSON request file offline. No API call.

Technical

metro api catalog --family contracts --json
metro api explain contracts.create --json
metro api validate contracts.create --file request.json --json
metro input normalize --api contracts.create --file request.yaml --json
Discovery
metro.schema / metro.api.catalog
Validation schema
metro.api.validation.v1
Metronome changes
None

When metro refuses

What the agent should say

English layer

"Metro blocked this operation on purpose. Exit code 2 means a safety gate failed - not a bug. Here is the one-line reason, and here are up to three commands to run next. I will not retry the live command until you approve the evidence chain."

Technical layer

metro docs explain refusal.troubleshooting --json
# stderr payload: summary, nextCommands[], blockers[], nextSafeStep
# schemaVersion: metro.refusal.v1 or metro.api.read.refusal.v1

Always get better

When the session is thrashing - draft the fix

World-class harnessing stays rooted in truth: reviewed catalog IDs, official docs.metronome.com sources, expected-vs-actual after writes, and upstream changelog coverage. When discovery costs more than a lasting shortcut, promote the codebase.

Trigger

Many greps, many docs hops, repeated Live API archaeology, or “I’ll check one more place” for the same shape of ask.

What to say

“This can be faster.” I can draft a PR that adds a metro command, shape, validator, or cookbook one-liner so the next person does not repeat this. You run/merge the code.

What to ship

Smallest durable path: catalog + sources + offline test (or TEAM-QUICKSTART / metro ops line). Not another one-off script outside metro.
